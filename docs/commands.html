Commands

Every xema command, 331 of them, as xema <command> --help describes it. Most need sudo. A command that changes the console's records goes through Manager, as the console does, so the same rules about who may change what apply.

Install and upgrade

Put Xema on a server, join it to a cluster, and keep it current.

init

xema init

Set up this server as the first node of a new cluster.

  • --address <address>: This machine's IP address as the other nodes reach it. Found when it has one LAN address, asked for when it has several.
  • --cluster <cluster>: The cluster's name. Defaults to this machine's name.
  • --name <name>: This node's name in the roster. Defaults to this machine's name.
  • --server <server>: The database server. Only used where no credentials are recorded yet; defaults to this machine.
  • --user <user>: The database login to create where none is recorded yet.
  • --dry-run: Say what would be set up, and change nothing.
  • --yes: Do not ask before writing.

join

xema join

Join this server to an existing cluster and set it up there.

  • --token <token>: The token xema cluster token printed on a node already in the cluster.
  • --address <address>: This machine's IP address as the other nodes reach it. Left out, it is the one on the cluster's subnet.
  • --name <name>: This node's name in the roster. Defaults to this machine's name.
  • --roles <roles>: Roles to give this node, comma separated. A joined node holds none until it is given some.
  • --yes: Do not ask before writing.

migrate

xema migrate

Bring this node up on this build: another version of Xema converted to it, or a new node joined. Within the installed version, the xema command itself is xema update and its components xema upgrade.

  • --address <address>: This machine's IP address as the other nodes reach it. Found when the first node has one LAN address, asked for when it has several; required on a node that joins.
  • --join <join>: A pass from xema cluster token, to join an existing cluster instead of creating one.
  • --cluster <cluster>: The cluster's name. Defaults to this machine's name; ignored with --join.
  • --name <name>: This node's name in the roster. Defaults to this machine's name.
  • --roles <roles>: Roles to give this node, comma separated. A cluster of one already holds every role.
  • --dry-run: Say what would happen, and change nothing.
  • --yes: Do not ask before writing.

update

xema update

Replace the xema command itself with the channel's newest, within its own version; another version is xema migrate, and Xema's components are xema upgrade.

  • --channel <channel>: dev or stable. Taken from this server's record when omitted.
  • --dry-run: Say which version it would replace the command with, and change nothing.

upgrade

xema upgrade [<components>…]

Upgrade Xema's components and the release's schema changes, within the installed version; another version is xema migrate, and the xema command itself is xema update.

  • [<components>…]: Upgrade only these, leaving every other component on the version it runs. The schema must already be at the release: xema database upgrade applies it.
  • --channel <channel>: dev or stable. Taken from this server's record when omitted.
  • --yes: Don't ask. Restarting a component drops the calls it is carrying.
  • --dry-run: List what would change, by version, and change nothing.

channel

xema channel

Show the release channel this server is recorded as taking releases from.

channel set

xema channel set <channel>

Record the release channel this server takes releases from.

  • <channel>: dev for the rolling channel, stable otherwise.

component list

xema component list

What is installed on this server, and what could be.

component install

xema component install <name>

Fetch a component's release and put it in place.

  • <name>: Which component. xema component list shows them.
  • --channel <channel>: dev or stable. Taken from this server's record when omitted.
  • --force: Install again even if it is already here.

component remove

xema component remove <name>

Take a component's code and unit off this server.

  • <name>: Which component.
  • --yes: Don't ask. Required when there is nobody to answer.

tokens

xema tokens

Show this node's token certificates and client secrets, and say plainly what is missing.

tokens create

xema tokens create

Make the certificates tokens are signed and encrypted with.

  • --years <years>: How long they last.
  • --force: Replace certificates already there. Every sign-in on the cluster ends.

tokens secrets

xema tokens secrets

Make the browser apps' client secrets, or replace them without a pause.

  • --rotate: Put a new secret first for every app, keeping the old ones, which Manager still accepts.
  • --retire: Keep only each app's first secret, once every node sends it.

keyring

xema keyring

Show this node's key ring certificate, and say plainly when there is none.

keyring create

xema keyring create

Make the certificate this cluster's key ring is encrypted with.

  • --years <years>: How long it lasts. Replacing it later means copying the new file to every node.
  • --force: Replace a certificate that is already there. Read what this costs first.

completion

xema completion [<shell>]

Print a shell completion script. xema completion install puts it where bash finds it.

  • [<shell>]: Shell to generate the script for: bash or zsh.

completion install

xema completion install

Tab completion for xema in bash, root's shells included: sudo xema completion install.

The cluster and its nodes

What each server runs, how the servers reach each other, and what they hold.

status

xema status

Show the status of the infra and Xema services (state, start time, CPU, memory).

  • --json: Emit machine-readable JSON instead of the tables — this is what the Manager serves to the dashboard.

discover

xema discover [<version>]

Run each version's discovery in order and stop at the last one found, which is this machine's current version; an older one found before it is still on the machine and is discovered too.

  • [<version>]: v1 or v2 to discover that version only; omitted, every version found here.

nodes

xema nodes

Ask every server in this cluster what it is running.

  • --seconds <seconds>: How long to wait for answers before calling the rest unreachable.

node roles

xema node roles

Show what this server is meant to run, beside what it actually is.

node role add

xema node role add <role>

Declare that this server should run something.

  • <role>: One of the roles listed by xema node roles.

node role remove

xema node role remove <role>

Declare that this server should not run something.

  • <role>: One of the roles listed by xema node roles.

node apply

xema node apply

Start what this server should run, and stop what it should not.

  • --dry-run: Print what would change and change nothing.
  • --yes: Don't ask. Required when there is nobody to answer.

node address

xema node address <node> [<address>]

Change the address the other nodes reach a node at, for the whole cluster.

  • <node>: The node's name or its id. Its own name is the ordinary case.
  • [<address>]: Where the other nodes should reach it: an IP address, optionally with a port. Left out only with --derive.
  • --derive: Derive the address instead of typing it: this machine's address on the subnet every other node of the cluster is on. Only for the node the command is run on, since only it can see its own interfaces. Refused when no such subnet exists — what remains is routed or tunnelled, and that is a decision, not a guess.

node claim

xema node claim

Records this machine as the node its bootstrap file names.

  • --yes: Do not ask before writing.

node wire

xema node wire

Write this node's settings from the cluster's wiring.

  • --dry-run: Print what would be written and write nothing.
  • --yes: Don't ask. Required when there is nobody to answer.
  • --restart: Restart this node's Xema services afterwards. Drops any calls it is carrying.

node files

xema node files

Place the unit, nginx, logrotate and Prometheus files this build carries, and start the host agent.

  • --dry-run: Say what would change and change nothing.

node check

xema node check

Check this node's token files and nginx files, and say how to put right what is wrong.

  • --fix: Place this build's nginx files where they differ, tested before nginx is reloaded.

node reset

xema node reset

Remove what was set up on this server. Databases, credentials, the key ring and backups are kept.

  • --force: Go ahead on a node that holds the database role, and remove that role too.
  • --dry-run: Say what would be removed, and change nothing.
  • --yes: Do not ask before removing.

node enable

xema node enable <node>

Let a node take part in the cluster again: xema node enable mini4.

  • <node>: The node, by name.

node disable

xema node disable <node>

Set a node aside, so the cluster gives it nothing to carry: xema node disable mini4.

  • <node>: The node, by name.
  • --yes: Answer yes to the confirmation up front.

node start

xema node start [<words>…]

Start services: xema node start bff, or --node mini4 for another node's.

  • [<words>…]: The services, --node with a node's name, and --yes. None named, here: every Xema service.

node stop

xema node stop [<words>…]

Stop services: xema node stop dialer --node mini4. Calls a stopped service carries drop.

  • [<words>…]: The services, --node with a node's name, and --yes. None named, here: every Xema service, asked first.

node restart

xema node restart [<words>…]

Restart services: xema node restart bff --node mini4. Calls a restarted service carries drop.

  • [<words>…]: The services, --node with a node's name, and --yes. None named, here: every Xema service, asked first.

node ssh

xema node ssh [<state>]

The SSH setting a node holds: xema node ssh. on or off changes it: xema node ssh off --node mini4.

  • [<state>]: on or off; left out, it is shown.
  • --node <node>: The node, by name; this one when not given.
  • --yes: Answer yes, up front, to turning SSH off.

node reboot

xema node reboot

Stop the platform in order and restart the machine: xema node reboot --node mini4. Every call the node carries drops.

  • --node <node>: The node, by name; this one when not given.
  • --yes: Answer yes to the confirmation up front.

node interfaces

xema node interfaces

A node's network interfaces, as SIP capture chooses from them: xema node interfaces.

  • --node <node>: The node, by name; this one when not given.

node capture

xema node capture

Whether a node is capturing SIP, and what: xema node capture.

  • --node <node>: The node, by name; this one when not given.

node capture start

xema node capture start

Start capturing SIP on a node: xema node capture start --port 5060 --record Failed --number 98480. What it keeps is listed by xema node captures.

  • --node <node>: The node, by name; this one when not given.
  • --device <device>: Interfaces to capture on, comma-separated; every usable one when not given.
  • --port <port>: Ports SIP is expected on, comma-separated.
  • --record <record>: Which calls to keep: All, Answered or Failed.
  • --number <number>: Phone numbers to narrow to, comma-separated; a call is kept when one is at either end.

node capture stop

xema node capture stop

Stop capturing SIP on a node: xema node capture stop.

  • --node <node>: The node, by name; this one when not given.

node captures

xema node captures

The captured calls, newest first, from every node's captures: xema node captures --search 98480 --outcome Failed.

  • --search <search>: Part of a number, a SIP call id or an address.
  • --outcome <outcome>: All, Answered or Failed.
  • --take <take>: How many to show, up to 500.

node capture show

xema node capture show <call>

One captured call, every SIP message in it: xema node capture show 01a1….

  • <call>: The call, as xema node captures lists it.

cluster status

xema cluster status

Show what this server belongs to, and who else is in it.

cluster token

xema cluster token

Mint a single-use pass for another server to join this cluster.

  • --cluster <cluster>: Which cluster the new server joins. Defaults to this node's.
  • --minutes <minutes>: How long it stays valid.
  • --label <label>: A note about who it was minted for.
  • --server <server>: How the joining server reaches this cluster's database. Defaults to the address recorded for this node, because the local setting is usually a loopback and would send the new server to its own database.
  • --address <address>: The joining server's IPv4 address, where it is outside this cluster's subnet — a DR node: the database is let in from it first. Run on the node holding the database.

cluster remove

xema cluster remove <node>

Take one server out of this cluster, and give what it held to another.

  • <node>: The node to remove, by name or by id.
  • --to <to>: Which node takes its trunks and devices. Defaults to this one.
  • --yes: Answer the confirmation.

cluster name

xema cluster name <name>

Name the cluster, as every screen shows it: xema cluster name "Ajmer site".

  • <name>: Its name.

cluster

xema cluster

The whole cluster: what it is made of, and what each server has made of it.

  • --seconds <seconds>: How long to wait for servers to say what they are running. Zero skips asking them, which is worth having when the broker is the thing that is broken.

cluster secret set

xema cluster secret set <purpose>

Record the password this cluster's nodes use for one of its shared parts.

  • <purpose>: redis or broker.
  • --secret <secret>: The password. Prompted for, unhidden, if not given.
  • --username <username>: The user, where the part has users. The broker does; Redis does not.
  • --generate: Make one up instead of asking for it — 32 characters, safe to paste.

cluster secret clear

xema cluster secret clear <purpose>

Forget a recorded password. The nodes then connect without one.

  • <purpose>: redis or broker.

bff failover

xema bff failover

Move the active BFF to another node. Calls continue; agents' connections move with it.

  • --to <to>: The node to move to, by name. Needed where more than one other node holds the bff role.
  • --yes: Do not ask before moving it.

broker queues

xema broker queues

Show Xema's queues on this broker, with the type each one currently has.

broker queues migrate

xema broker queues migrate

Move Xema's classic queues to quorum, so they survive a broker node going away.

  • --yes: Don't ask. Required when there's nobody to answer.
  • --dry-run: Print what would be deleted, and delete nothing.
  • --force: Delete a queue even with messages still in it, losing them.

hosts

xema hosts

The hosts every service answers at: xema hosts.

hosts limit

xema hosts limit [<hosts>…]

Limit the hosts to the cluster's own and any named: xema hosts limit, xema hosts limit lb.example.com.

  • [<hosts>…]: Host names or IP addresses beyond the cluster's own, added to those already named.

hosts any

xema hosts any

Answer at any host, the default: xema hosts any. The named hosts are kept for a later limit.

hosts add

xema hosts add <host>

Name a host beyond the cluster's own: xema hosts add lb.example.com.

  • <host>: A host name or IP address.

hosts remove

xema hosts remove <host>

Stop naming a host: xema hosts remove lb.example.com. The cluster's own cannot be removed.

  • <host>: A host named with add or limit.

cors

xema cors

Which pages may call from another origin: xema cors.

cors add

xema cors add <origin>

Let another site's pages call: xema cors add https://crm.example.com.

  • <origin>: Scheme, host and any port, as the browser sends it.

cors remove

xema cors remove <origin>

Stop another site's pages calling: xema cors remove https://crm.example.com.

  • <origin>: An origin added with add.

cors any

xema cors any

Let any site's pages call: xema cors any. The origins added are kept for a later limit.

cors limit

xema cors limit

Only the cluster's own pages and those added, the default: xema cors limit.

dns

xema dns

The DNS of the node Manager runs on: xema dns.

dns servers

xema dns servers <servers>

The name servers of the node Manager runs on: xema dns servers 10.0.0.2,10.0.0.3.

  • <servers>: The servers, comma-separated.

dns domains

xema dns domains <domains>

The search domains of the node Manager runs on: xema dns domains site.local.

  • <domains>: The domains, comma-separated.

time

xema time

A node's clock, zone and time sync: xema time, or --node mini4.

  • --node <node>: The node, by name; this one when not given.

time clocks

xema time clocks

Every node's clock against the BFF's: xema time clocks.

time zone

xema time zone <zone>

Move a node to another time zone: xema time zone Asia/Kolkata. Its services keep running.

  • <zone>: The zone, as tzdata names it.
  • --node <node>: The node, by name; this one when not given.

time sync

xema time sync <state>

Turn a node's time sync on or off: xema time sync on.

  • <state>: on or off.
  • --node <node>: The node, by name; this one when not given.

time servers

xema time servers [<servers>]

The servers a node takes its time from: xema time servers 0.pool.ntp.org,1.pool.ntp.org. None given hands the question back to the machine's own configuration.

  • [<servers>]: The servers, comma-separated.
  • --node <node>: The node, by name; this one when not given.

binding add

xema binding add <address> <purpose>

Bind an address on a node to a purpose: xema binding add 10.0.0.5 sip --node mini4 --host-name sip.site.local.

  • <address>: One of the node's addresses.
  • <purpose>: What it carries, as xema bindings names purposes.
  • --node <node>: The node, by name; this one when not given.
  • --host-name <host-name>: The name it answers to.
  • --description <description>: What it is for.

binding remove

xema binding remove <address>

Remove a node's binding: xema binding remove 10.0.0.5 --node mini4. One a trunk uses is refused by Manager.

  • <address>: The bound address.
  • --node <node>: The node, by name; this one when not given.

bindings apply

xema bindings apply

Apply this node's network bindings: the node agent writes the SIP listeners and trunk addresses they name and reloads PJSIP. A listener whose address another program still holds is reported, not forced. Run as root.

bindings

xema bindings

A node's network bindings, what uses each, and whether it has applied them: xema bindings --node mini4.

  • --node <node>: The node, by name; this one when not given.

Running services

Start and stop Xema's services, and read what they log.

start

xema start [<service>…]

Start services. With none named, every Xema service on this node; starting drops no call, so nothing is asked.

  • [<service>…]: Services (manager, xema-manager, redis) or a group (infra, all). None: every Xema service.

stop

xema stop [<service>…]

Stop services. With none named, every Xema service on this node, after asking: the calls they carry drop.

  • [<service>…]: Services (manager, xema-manager, redis) or a group (infra, all). None: every Xema service.
  • --yes: Do not ask before stopping every Xema service.

restart

xema restart [<service>…]

Restart services. With none named, every Xema service on this node, after asking: the calls they carry drop.

  • [<service>…]: Services (manager, xema-manager, redis) or a group (infra, all). None: every Xema service.
  • --yes: Do not ask before restarting every Xema service.

shutdown

xema shutdown

Stop every Xema service in order, then power the machine off — or restart it with --reboot.

  • --yes: Don't ask. Required when there's nobody to answer.
  • --reboot: Restart instead of powering off.
  • --dry-run: Print what would be stopped, and stop nothing.

logs

xema logs [<service>]

Show journal logs for the Xema services — a live two-pane browser when run in a terminal.

  • [<service>]: Service to select initially, e.g. manager or xema-manager.
  • --lines <lines>: -n, Number of recent log lines to load.
  • --follow: -f, Keep following new output (only relevant when output is redirected).

logs backup

xema logs backup

Copy the logs database, which the conversion does not touch.

crash-reports

xema crash-reports

Browse restart reasons and recent errors for each Xema service.

  • --lines <lines>: -n, How many recent journal lines to scan per service.

loglevel show

xema loglevel show [<words>…]

One service's levels, by category: xema loglevel bff.

  • [<words>…]: The service, and --node with a node's name.

loglevel set

xema loglevel set [<words>…]

Set categories' levels in one service: xema loglevel set bff Default=Debug Xema.Bff.Queues=Trace. A category set to nothing (Microsoft=) is taken out; the rest of the block is kept.

  • [<words>…]: The service, Category=Level for each, and --node with a node's name.

loglevels

xema loglevels

The services whose log levels can be changed: xema loglevels, or --node mini4.

  • --node <node>: The node, by name; the one Manager runs on when not given.

Backups and data

Backups, the databases, call records, and what comes across from V1.

backup

xema backup

Back up this node entirely: every database on its server that holds a table, the call record where it is on a server of its own, and the files it cannot download again. Each part is taken and reported even when one before it failed, and the exit code is the worst of them.

backup list

xema backup list

xema backup list: every run on this machine, newest first.

  • --json: The runs as a JSON array, which is what the node agent reads.

backup prune

xema backup prune

xema backup prune --keep N: keeps the N newest complete runs and deletes every run older than them.

  • --keep <keep>: How many complete runs to keep. At least one.

files backup

xema files backup

Back up the files this node cannot download again. xema backup runs this after the databases.

metrics backup

xema metrics backup

Copy the metrics database, which the conversion does not touch and which is usually the largest on the server.

database connect

xema database connect

Record how this server reaches its database, check that it works, and set up the schema.

  • --server <server>: The database host. localhost for the ordinary single server.
  • --user <user>: The MariaDB user Xema connects as.
  • --pass <pass>: Its password. Prompted for if left out, which keeps it out of shell history.
  • --provision: Create the user first, with a password nobody has to choose or remember. Logs in to MariaDB as whoever is running the command, so it needs a login that may create users.
  • --trusted-user: Log in to MariaDB as root instead of as yourself. Needed when your own Linux login has no rights to create a user; run the whole command under sudo for it to work.
  • --from-v1: Take the server, user and password from the V1 installation on this machine rather than being told them. Every V1 service signs in as the one user V1's installer made, so on an upgraded server the right credentials already exist and making new ones is the only wrong move.

database

xema database

Show what this server is set to connect to. Never the password.

database tables

xema database tables

List the tables V2's schemas own, one per line: server, database and table, separated by tabs. Read from this build's schemas; nothing is written.

database upgrade

xema database upgrade

Apply this release's schema changes: every schema when all of them are additive, or only the schemas named, whatever they change. Components keep the versions they run.

  • --allow-narrowing: Also apply migrations that shorten columns. A value that does not fit fails the migration.
  • --dry-run: List the pending migrations and whether they can be applied, and change nothing.
  • --yes: Do not ask before applying.
  • --schemas <schemas>: Apply only these, whatever their changes are, and leave every other schema as it is. What uses a schema whose change is destructive may fail until it is upgraded. xema database upgrade --dry-run lists them.

database backup

xema database backup

Copy the databases Database.Migrate converts, before it converts them.

cdr

xema cdr

Show what this node is set to connect to for the CDR. Never the password.

cdr connect

xema cdr connect

Record which database server this node's call record is kept on, and check it works.

  • --server <server>: The server the CDR is on. Left out, this records this node's own database.
  • --user <user>: The MariaDB user SimpleCdr connects as.
  • --pass <pass>: Its password. Prompted for if left out, which keeps it out of shell history.
  • --role <role>: Which copy of the call record this node's recorder keeps: primary, ha or dr. One node each.
  • --allow-narrowing: Also apply schema changes that shorten columns, as xema database upgrade allows. A value that does not fit fails the change.

cdr backup

xema cdr backup

Copy the call record, which the conversion changes and database backup does not cover.

cdr copy

xema cdr copy

Copy the call record's history from another copy into this node's: for a new ha or dr copy, once its recorder is running. Rows it already has are skipped. Run as root.

  • --from-server <from-server>: The server the history is on. Defaults to the cluster's database server.
  • --from-user <from-user>: Its MariaDB user. Defaults to this node's cluster user; with another, the password is asked for.
  • --from-database <from-database>: The database the history is in.
  • --yes: Do not ask before copying.

cdr columns

xema cdr columns

Each spare column of the call record and the variable it is filled from: xema cdr columns.

cdr column

xema cdr column <column> [<variable>]

Fill a spare column from a channel variable, or leave it empty with no variable: xema cdr column Text1 CUSTOMER_ID. The rest are kept.

  • <column>: The column, as xema cdr columns lists it.
  • [<variable>]: The channel variable; left out, the column is filled from nothing.

cdr script

xema cdr script

The SQL run against the call records once a call is written: xema cdr script. --set script.sql replaces it, an empty file stops it, and --try script.sql runs a script once and undoes it, saying what it would have touched.

  • --set <set>: A file whose SQL becomes the script.
  • --@try <@try>

v2cdr correct

xema v2cdr correct

Re-key the calls recorded under ids that are not UUID v7, so reports find them. Run as root.

v1cdr migrate

xema v1cdr migrate

Copy V1's call-record history into this build's tables, while V2 serves. Run as root.

  • --from-start: Read every table from its start again, trying each refused row once more: for after a refusal's cause is fixed. Rows already copied are written again as the same keys, which changes nothing.

v1data migrate

xema v1data migrate

Copy V1's dataset rows into this build's tables, while V2 serves. Run as root.

v1reports migrate

xema v1reports migrate

Convert a converted V1 site's saved reports and post-processing script to this version's call-record tables. Examines and writes the before and after of each, changing nothing, unless --apply or --restore is given. Run as root.

  • --apply: Write the reports and the script that convert cleanly, keeping their originals first.
  • --restore: Put back the originals an earlier --apply kept, wherever they have not been changed since.
  • --dry-run: Examine and write the before and after of each, changing nothing. This is the default.

People

Agents, teams, skills, roles and processes, as the console sets them.

agents

xema agents

The agents, their teams and the skills they take calls on: xema agents.

agent show

xema agent show <user-name>

One agent: their name, team, phone, skills and roles: xema agent show vasu.

  • <user-name>: The agent, by username.

agent add

xema agent add <user-name>

Add an agent who signs in to an Agent UI with this username and a password: xema agent add vasu --name "Vasu" --team Sales --skill English,Billing, or --like vasu1 for another agent's team and skills.

  • <user-name>: The username they sign in with.
  • --name <name>: Their name, as the console shows it. Asked at a terminal when not given.
  • --team <team>: The team they are in, by name. Asked at a terminal when neither this nor --like is given.
  • --skill <skill>: The skills they take calls on, by name, comma-separated.
  • --like <like>: An agent, by username, whose team and skills they get; --team and --skill override either.

Webhooks, CRMs, lookups and the other apps a call can reach, and the AI behind them.

webhooks

xema webhooks

The webhooks: xema webhooks.

webhook show

xema webhook show <webhook>

One webhook, every field: xema webhook show crm-push.

  • <webhook>: The webhook, by name.

webhook add

xema webhook add [<words>…]

Add a webhook: xema webhook add crm-push verb=post url=https://crm.example/hook.

  • [<words>…]: Its name, then field=value; xema webhook fields lists the fields.

webhook set

xema webhook set [<words>…]

Change a webhook: xema webhook set crm-push url=https://crm.example/v2. What is not named is kept.

  • [<words>…]: The webhook, by name, then field=value.

webhook remove

xema webhook remove <webhook>

Remove a webhook.

  • <webhook>: The webhook, by name.
  • --yes: Answer yes to the confirmation up front.

One report's definition, its query among it: xema report show "Agent summary".

  • <report>: The report, by name.

Add a report: xema report add "Calls by hour" reportGroup=Calls template=generic queryText="select ...".

  • [<words>…]: Its name, then field=value; xema report fields lists them.

report set

xema report set [<words>…]

Change a report: xema report set "Calls by hour" filterOptions="from-date;to-date".

  • [<words>…]: The report, by name, then field=value.

report remove

xema report remove <report>

Remove a report.

  • <report>: The report, by name.
  • --yes: Answer yes to the confirmation up front.

report fields

xema report fields

What can be set on a report.

report run

xema report run <report>

Run a report: xema report run "Agent summary" --from 2026-10-01 --to 2026-10-15, shown as a table, or written to a file with --csv calls.csv. Each filter is the one its definition offers.

  • <report>: The report, by name.
  • --from <from>: The first day, as a date.
  • --to <to>: The last day, as a date.
  • --agent <agent>: Only this agent, by username.
  • --phone <phone>: Only this phone.
  • --ani <ani>: Only calls from this number.
  • --dni <dni>: Only calls to this number.
  • --csv <csv>: Write the rows to this file as CSV rather than show them.

report grant

xema report grant <report> <scope> <who>

Share a report with a user or a role: xema report grant "Agent summary" role Supervisor.

  • <report>: The report, by name.
  • <scope>: user or role.
  • <who>: The username, or the role's name.

report revoke

xema report revoke <report> <scope> <who>

Stop sharing a report with a user or a role: xema report revoke "Agent summary" user asha.

  • <report>: The report, by name.
  • <scope>: user or role.
  • <who>: The username, or the role's name.
