Switches

Some of Xema's behaviour is switched on or off for the whole cluster. Each switch is off until someone turns it on, except crmDashboard and acceptedPromptSkipsBreakLimits, which are on until someone turns them off. Each is set from any server in the cluster with the xema command. A change takes effect within seconds, on every server, without restarting anything.

They are all under one command:

xema flags                       # every switch, and whether it is on
xema flags fields                # the switches that can be set
xema flags set <switch>=on       # turn one on (off, true, false, yes and no also work)

More than one switch can be set at once: xema flags set callHistory=on missedCalls=on.

Upgrading from a release before xema flags: a switch that was turned on before is off after the upgrade, and is turned on again with xema flags set. Run xema flags before upgrading and note what is on.

Queue recovery

There is no switch for this. When the queue service restarts while callers are waiting (during an upgrade, after a crash, or when its connection to the phone system drops and comes back), each waiting caller goes back into the queue they were in, in the place they had, and their waiting time carries on from when they first joined.

A caller goes back to the call flow that put them in the queue only when Xema cannot tell which queue they were in, or when they joined it. A caller whose call an agent had already answered is left to be connected to that agent. A caller who rings in while the queue service is down goes on to the step after the queue in their flow.

A caller put back into their queue is not counted as a second arrival: queue reports and call records show one wait.

Upgrading from a release with the requeueOrphans switch: the switch is gone, and callers go back into their queue whether it was on or off.

Agent features

Which optional parts of the agent's screen the cluster offers, and one rule for agents' phones.

Switch When on
crmDashboard Calls reach agents with their queue's CRM pages. On by default. Off, a call carries none, whatever its queue has. A change applies from the next call.
callHistory Agents can see their own call history.
missedCalls Agents are shown the calls they did not answer.
myDay Agents are shown a summary of their day so far.
demoContent Content marked as demonstration material is shown, across the cluster.
requirePhoneOnAgentAddress A phone that registered from a different address from the one the agent signed in from is refused. 
xema flags set myDay=on

Agent pauses

How time on a ban or a break counts. Each is set for the cluster with xema flags. A process can also state its own value, and then that value counts for the agents in that process instead of the cluster's.

Switch When on
banCountsAsBreak Time on a ban counts as break time. Off, a ban is its own time.
acceptedPromptSkipsBreakLimits A break an agent takes by accepting a prompt does not count against the team's break limits. On by default.
signedOutBanCountsAsLogin Time on a ban while the agent is signed out counts as login time. 
xema flags set banCountsAsBreak=on
