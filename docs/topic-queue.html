queue

A queue holds callers until an agent with the required skills is available. A queue can require several skills, for example a language and a product. Only agents who have every required skill take its calls.

When several queues need the same agent, the queue with the higher weight is served first.

Steps

  • Waiting: hold music, announcements, promotions, and caller actions.
  • Agents: the required skills and the weight. Sticky agent routes a returning caller to the agent they last spoke to.
  • In call: the alert the agent hears and the actions the agent is allowed.
  • Recording: whether calls are recorded.
  • After the call: the maximum dispose time, the SLA and AHT targets, and abandoned calls. Without a dispose time, the call is disposed when it ends.
  • Agent screen: the queue's colour and pattern, and the call details shown to the agent. These settings do not affect call handling.

Process policy

A queue in a process follows the process's policy while calls run. If the process makes recording mandatory, or does not allow automatic dispose, the queue's own setting has no effect, and the editor says so beside it. The queue is still saved as you set it.

Targets

  • SLA target: the time, in seconds, within which a call should be answered. The SLA target percent is the share of calls to answer within that time.
  • AHT target: the expected average handling time per call, in seconds.

Queue cards

  • A red Record badge means the queue's calls are recorded. The bar beside the name shows the queue's colour and pattern.
  • Each card lists the required skills and the targets that are enabled: SLA, AHT and maximum dispose time (shown as Wrap).
  • The chips show which in-call actions agents are allowed; a highlighted chip is allowed. The number in the corner is the queue's weight, shown when it is not zero.

Live status

  • Green means the queue is running and accepting calls. The numbers show the callers waiting now and the abandoned calls per minute. Red means the queue is stopped.
  • The status refreshes every 15 seconds.

Features

Only enabled features are listed: prompts, promotions, agent call tools, targets and abandoned-call capture.

Tools

  • Caller actions are keys a waiting caller can press, for example to request a callback or switch to another flow.
  • Agent actions are the equivalent for the agent on the call, such as transfers and flow switches.
  • CRM URLs open the caller's record in your CRM when the call is connected to an agent.
  • The counts show how many of each are configured.

Commands

  • xema queue add
  • xema queue fields
  • xema queue remove
  • xema queue set
  • xema queue show
  • xema queues
