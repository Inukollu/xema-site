cluster

A cluster is a group of servers at one location that work as one contact center. Servers in a cluster share settings and records, so a call arriving at any server can be handled by an agent signed in on any other. Most installations use a single server and need no changes here.

A cluster is shown by its cluster identifier until it is given a name. A cluster keeps working if it loses contact with your other clusters, and its agents continue to answer its calls. Work cannot be passed between clusters until the connection is restored, which happens automatically.

Server roles

Each server has roles. A change to a role is saved at once. The server applies it shortly afterwards and starts or stops that part of the system.

A server that is unreachable applies the change when it reconnects.

Last contact

Each server reports in regularly. A server that has not reported for a while is shown with a dashed outline and the time since its last report. This usually means the server is switched off or unreachable.

In service

Taking a server out of service disables it without deleting it. Its history and roles are kept, so it can be returned to service without being set up again. Use this during maintenance.

Infrastructure

Some components are shown for information only: the shared database, the message broker and the telephony engine. They hold your data and live calls, so moving one needs planning and is not done in Xema Manager. Contact your support provider if one needs to be moved.
