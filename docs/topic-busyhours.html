busyhours

The busy hour is the hour of the day with the most traffic. Staffing, trunk capacity and service targets are usually planned for it. These settings control how the Busy Hours dashboard in Data Portal reports it.

Method

  • Both shows your declared window next to the busiest hour calculated from traffic, so you can compare them.
  • Computed calculates the busy hour from recorded traffic only. It uses the time-consistent busy hour: the clock hour with the most traffic on average across the days observed, not the peak hour of a single day.
  • Declared reports on the window you set and calculates nothing. Use it when the busy period is set by the business.

Declared busy window

The hours the business treats as its busy period, for example 10:00 to 13:00. Until is the hour the window ends, so this example covers 10:00, 11:00 and 12:00.

Computed busy hour

  • Search from and Search until limit the hours searched. Keep the full day unless the contact center is open for only part of it, so that an overnight hour is never selected.
  • Days observed is the period the dashboard opens with. 30 days is typical; a longer period gives a steadier result, a shorter one reflects recent changes sooner.
  • Count weekends sets whether Saturdays and Sundays are included. Disable it when weekend traffic differs from weekdays.

Where it is shown

The Busy Hours dashboard in Data Portal shows calls and traffic by hour, the busy period, and each queue's busiest hour. Changes apply within a minute; users with the dashboard open see them after refreshing.

Commands

  • xema busyhours
  • xema busyhours fields
  • xema busyhours set
