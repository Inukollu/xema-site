flow

A flow is a call flow: a named set of blocks, each a group of steps, that decides what happens to a call. A call enters at the First block and runs its steps from top to bottom. It stays in the flow until a step sends it elsewhere (another block, a queue or another flow) or the call is hung up.

A new flow is empty. Its blocks and steps are added in one of the editors, and callers are not affected until the flow is published. A flow with no first block hangs up every call, so route a number to it only after it has been built.

Name and description

  • The name cannot be changed later. Steps in other flows, routed numbers and dialers refer to the flow by name, so choose a name that is easy to recognise in a list.
  • Description says what the flow is for and who it serves. It is never played to callers and can be changed at any time.
  • Published version is the version of the flow currently handling calls. It increases by one each time a change is published.

Blocks

A block is a named group of steps. GoTo, Menu, If, IfTime and Navigate steps refer to a block by its name, so choose a name that is easy to recognise.

When a block's last step finishes, the call is hung up. A block does not continue into the next block, so every path must end deliberately, by sending the call on or hanging up. The order of blocks does not affect routing.

  • With no First block selected, calls to the flow are hung up immediately.
  • The Start tag marks the block where calls enter.
  • A faded Unreachable tag means no step leads to that block. It never runs until a step points to it or it becomes the first block.
  • Deleting a block does not update the steps that pointed to it. Update those steps, or calls reaching them are dropped.

Steps

Each step has an Action. Most actions do nothing until configured: a Playback with no audio, or a GoTo with no destination, is skipped.

A step's Description is a note for administrators and is not used during the call.

An IfTime step sends the call to its Match block when the server's clock is inside every range it sets, and to its No match block otherwise. Leave a range empty for any:

  • Time of day, such as 09:00-17:30.
  • Days of the week, such as mon-fri, or several joined by &, such as mon&wed&fri.
  • Days of the month, such as 1-15.
  • Months, such as jan-mar.

Markers

A marker records that the call passed through the block, building the path the call took. The path is stored with the call for reporting.

Add markers only to the blocks you want to report on, to keep the path readable, such as Main Menu | Billing | Agent.

Tracing a call

Tracing requires both of the following:

  • Enable Enable flow debug. This adds diagnostics to the flow but does not start tracing.
  • Add a Debug step where tracing should start. From that point the call logs each block it enters and the path so far.

The setting alone produces no trace. Remove the Debug step when you have finished.

Editors

  • View shows the flow as a read-only diagram, a safe way to review a flow that is handling calls.
  • Visual editor edits the flow on the diagram.
  • Classic editor edits the flow as a list of blocks.
  • JSON editor edits the stored document directly.

All the editors work on the same flow. You can switch between them, and unpublished edits are kept.

In the diagram, each card is a block, and the rows inside it are its steps, in the order they run. A line connects a step to the block it sends the call to. Where a step has several options, each line has its own colour and the option's name. An icon at the end of a step means the call leaves the flow there: to a queue, another flow, another XApp, or a hang-up.

The JSON form

The JSON form is the flow as it is stored. The other editors change this same document, and everything in it is shown in those editors. It is useful for:

  • Moving several steps from one block to another, with cut and paste.
  • Copying a block from one flow to another.
  • Changing something the other editors do not offer.

The flow updates as you type. While the text is not valid JSON, the flow is left unchanged and the error is shown, and Show diff is unavailable.

Blocks are identified by their id, and steps refer to their destination block by that id. Changing an id, or pasting a block with an id already in use, breaks the steps that lead to it. Check the diagram to confirm the flow is still connected.

Publishing

Edits are not live. Until a flow is published, calls use the current version. Show diff compares your edits with the version currently handling calls, in the flow's stored form. Lines shaded green are added by your version; lines shaded red are removed. A deleted block, or a step that lost its destination, appears as a red line.

  • Comment is a short description of the change. It is stored with the version and helps to identify it in the version list later. Optional, but recommended.
  • Save publishes the flow: its version number goes up by one and new calls use it immediately. Calls in progress continue on the previous version.
  • Cancel keeps the published version and keeps your edits, which are still there the next time the flow is opened.

Versions

Each time a flow is published, a version is saved with its publish date and comment.

History lists every published version, newest first, and compares each with the one before it. Compare compares any two versions, for example the current version with one from months ago. It is available once the flow has been published twice. Neither changes the flow. Each lists the blocks that differ:

  • Added: a block that is new in the newer version.
  • Removed: a block that was deleted.
  • Changed: a block whose steps, or their order, changed.
  • Entry: calls now enter at a different block.

The steps of each changed block are listed below it, showing which step was added, removed, edited or moved. Renamed means the block was renamed. Published without the steps being touched means the version made no change to the flow's steps.

The line-by-line comparison shows the older version on the left and the newer on the right. Lines shaded green were added; lines shaded red were removed. Settings a step does not use are hidden on both sides, so only the differences stand out.

An earlier version can be restored. The changes are shown first, and the version is published only when it is saved. Restoring publishes the earlier flow as a new version, so no history is lost.
