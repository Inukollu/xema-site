trunk

A trunk is the SIP connection between Xema and a carrier. Calls come in and go out through it. Each trunk has one or more DNIs that route incoming calls.

A trunk's details show its reachability, its latency, its DNIs and its missed calls. In the list of trunks, the large number is the trunk's count of DNIs. Its type (SIP client, carrier, or carrier behind a SIP realm) and its description are shown below the name.

Type

The kind of connection at the other end. The type decides which fields apply; fields a type does not use are hidden.

  • SIP client with auth: the remote end registers with Xema and is authenticated. Only a password is needed. The trunk name is the username, and no address is needed because the remote end connects in. Useful for simulating external calls.
  • Carrier trunk: a carrier used for outbound calls. Requires the carrier's remote IP and a codec list.
  • Carrier behind a SIP realm: the realm handles the connection to the carrier, so you select the realm instead of entering an address. No registration or authentication is needed. SIP realms are set up under Network.

Registration

For a carrier trunk:

  • Enable Register with the carrier if the carrier requires registration, and enter the user ID and password the carrier provided.
  • Leave it disabled if the carrier identifies this server by its IP address. No credentials are sent, and the fields are hidden.

Connection

  • Codecs is written directly to the endpoint's allow list. The default suits most carriers; change it only if the carrier requires it. Avoid all: it allows codecs that need transcoding on every call, which causes audio problems under load.
  • Dial prefix is added before outbound numbers dialled through the trunk. Leave it empty if the carrier expects plain numbers.
  • SIP domain and Pilot number are for reference only and do not change the trunk configuration.
  • Server appears only on a cluster with more than one server. It is the server the carrier's circuit is connected to, and only that server configures the trunk.

Carrier limits

  • Max channels, Max inbound and Max outbound are the calls the carrier allows at once: in all, and in each direction. Calls per second is how many calls may start in one second. Leave any of them empty for no limit. Where max channels is set, inbound and outbound are each at most that.
  • The numbers dialled in on and presented are kept in Phone number pools, not on the trunk. Map a pool to the trunk in the trunk's Phone number pools section, or on the pool's own page. A pool mapped to a trunk keeps the trunk from being deleted.

Health

  • The status dot shows whether the trunk's remote end answers pings: green when reachable, red when not.
  • RTT, Loss and Jitter are measured from those pings. Rising values usually mean call quality problems.
  • Trace route, on the Overview tab, runs a network trace to the remote end, to find where traffic stops when the trunk is unreachable.
  • Health refreshes every 15 seconds.

DNIs and missed calls

  • The DNIs are the numbers that arrive on the trunk, each with the XApp it routes to.
  • A pulsing green dot means the number accepts calls; red means it is disabled. Only a disabled number can be enabled again or deleted.
  • Missed calls are calls that arrived on the trunk but were not routed. The count covers the last 5 minutes.

Calls a process takes

A process takes calls from outside in one of two ways:

  • A whole trunk. The process takes every call on that trunk, and no other process can take it.
  • Numbers on a shared trunk. Several processes share the trunk, and each takes the calls to the numbers it names. A number belongs to one process only.

An agent's call, a dialer's call and every record of them belong to the process the call came in by.

Only a manager or an administrator changes which trunks and numbers a process takes.
