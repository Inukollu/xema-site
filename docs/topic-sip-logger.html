sip-logger

SIP Logger captures SIP signalling arriving at a server. It stores the complete message exchange of each call, from the first INVITE to the last message, so you can see what happened.

It is most useful when setting up a system or a trunk. Calls that are rejected before they reach a queue are not recorded anywhere else.

Recording

  • A recording runs from Start recording until Stop. A reboot or a service restart also stops it.
  • Interface is the network interface to capture on. Keep Every interface unless you know which interface the calls use.
  • Ports are the SIP ports to capture, usually 5060. Separate several ports with commas.
  • Keep selects which calls are stored. Calls that never connected is the usual choice: it keeps the rejected calls and leaves out successful ones on a busy system.
  • Involving limits the capture to one or more numbers, separated by commas. A call is kept when the number appears as either the caller or the dialled number. A partial number is enough, so eight digits also match the number with a country code or extension. Leave it empty to include all calls.
  • While recording, Xema shows the counts so far. Calls are listed when they finish.
  • Only one recording can run at a time on the whole system. While another user is recording, nobody can start another. Stopping it stops their recording.
  • A dot beside a call marks it as captured by the current recording. The count beside the search box shows how many such calls are listed.
  • The counter shows attempts, not calls, because one call can involve several attempts. For example, a phone whose first offer is rejected and that retries at once makes two attempts.
  • Kept is the number of attempts stored. It is lower than the number of attempts whenever Keep is set to anything other than Every call.

Call list

  • Calls are listed newest first. Result shows whether the call was answered. Never connected includes rejected, cancelled and unanswered calls.
  • Came from is the source address of the call. For a rejected call, check this address first to confirm the caller is who you expect.
  • Search matches a caller or dialled number, an address or a SIP Call-ID. Showing filters the calls by result.

Message exchange

  • Each call holds the complete exchange in order. The rejection reason is included, for example 403 Forbidden, 404 Not Found, or 488 when the two ends could not agree on an audio format.
  • Rejections are shown in red and the presented caller ID in green. A key and an explanation of common rejections are shown beside the call.
  • Copy copies the exchange to the clipboard. Carriers usually ask for this when you report a problem with their calls.

Notes

  • Record only while investigating a problem. Every recorded call is stored until you delete it.
  • The stored data includes callers' numbers, so handle it as you would any call record.
  • Calls over encrypted connections (TLS) cannot be captured.
  • If SIP Logger is not responding, its service is not running. Start it under Services.
