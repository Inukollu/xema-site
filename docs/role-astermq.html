AsterMQ

AsterMQ carries the phone system's events on its server to the rest of the cluster. Every other service learns what happened on a call through it.

Given automatically to a server that carries a trunk. When a trunk is assigned to a server (sudo xema trunk assign <trunk> --node <server>), that server is given every service a phone system's server runs, this one among them. It is given once and kept: unassigning the server's last trunk does not take it away again. xema node role remove does.

Putting it on a server

sudo xema node role add astermq
sudo xema node apply

node role add records that this server should run it, and node apply starts it. If xema component list shows it is not installed here, install it between the two:

sudo xema component install astermq

A server can also be given it as it joins: sudo xema join ... --roles astermq,....

Taking it off

sudo xema node role remove astermq
sudo xema node apply

Checking it

xema node roles          # what this server should run, beside what it runs
xema status              # every service on this server, running or not
xema logs astermq

Restarting it

sudo xema restart astermq                       # on this server
sudo xema node restart astermq --node <server>  # on another one

Restarting drops the calls it is carrying.
