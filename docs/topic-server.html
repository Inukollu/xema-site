server

The server settings are the operating system's settings for a server: its name, its time and its SSH access. The server can also be restarted from here, with Restart host.

Values are read from the running system each time they are shown. A change takes effect at once, as if the command had been run on the server. Nothing is staged and there is no separate save.

Name

  • Host name is the server's name. It is shown as the title and on the sign-in page, and identifies the server when you have several open.
  • A new name takes effect for the operating system at once. Xema's services read the name only at startup, so they show the old name until the server is restarted with Restart host.
  • A name can contain letters, digits and hyphens, optionally followed by a domain. Certificates, DNS records and anything else that refers to the server by its old name are not updated. Check them before renaming a server in use.

Time

  • The clock shows the server's time, not your computer's. Call times are always taken from the server.
  • Time zone is the server's local time zone. Call records, reports and schedules use it, so changing it changes the meaning of every stored time from then on.
  • A time zone change applies to the operating system at once, but not to Xema's services, which read it at startup. A warning shows until the server is restarted. Change the time zone at a quiet time: a change during the day splits that day's records across two zones.
  • Time sync keeps the clock correct by querying a time server. Leave it enabled. Without it the clock drifts, so call records, recordings and reports no longer match the phone system.
  • The clock's status shows the offset from the time server, which server is used, and its stratum (the number of steps from a reference clock). An offset under 0.1 seconds is normal. At one second or more, call times are wrong. The reading updates every 30 seconds. If the offset does not decrease, the time server is too far away or unreachable.
  • Time servers are shown only while sync is enabled. Leave the list empty to use the defaults. Xema shows which servers are in use: either those assigned by the network, or the operating system's defaults. Set your own when neither works, for example on a network with no internet access but with its own time server. List the nearest first, separated by spaces.
  • If the server uses a time client other than systemd's, the time servers are shown but cannot be edited.

SSH

  • SSH server shows whether the server accepts SSH connections. Where SSH is socket-activated, this setting controls the socket.
  • When SSH is disabled, the setting is kept. Manager checks every few seconds and stops SSH again if anything starts it, such as an upgrade, the socket or a user at the console. Xema shows how long the setting has been in effect and how often SSH was stopped.
  • The server's own startup configuration is not changed. After a restart, the server starts as configured, and the setting is enforced again as soon as Manager is running.
  • SSH is disabled on a new installation until it is enabled.
  • Without SSH you cannot connect from a terminal or deploy over SSH. The browser shell still works and can enable SSH again, as long as Manager is running.
