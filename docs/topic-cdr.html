cdr

Xema writes a call detail record (CDR) for every call. Two settings shape it: CDR variables, which fill spare columns from channel variables, and a post-processing script, which runs after each record is written.

CDR variables

In addition to the standard fields (caller, time, duration, agent), the call record has spare columns that you can map to channel variables.

  • Enter a channel variable name against a column. When a call ends, the variable's value is written to that column.
  • The variable is set during the call, by an XApp, the dial plan or another step. The name must match exactly.
  • Unmapped columns stay empty. Each column type shows the columns in use and one spare; when you fill the spare, another one appears.
  • Choose a column type that suits the value. A number in a whole-number column is stored as a number; text in a date column is stored as empty.
  • These columns are part of the call record, so reports can use them and name them on the report's own page.

Post-processing script

SQL that runs against the call records after each call is written. Use it for updates that need the complete call, such as filling a column from other fields or from another table.

  • Write {CallId} where the call's ID belongs. It is replaced with the ID of the call just written, so the script should change only that call.
  • A script without {CallId} does not run. This prevents a script from changing the whole table.
  • Leave it empty to run nothing.
  • Keep it fast. It runs once per call while records are being written, so a slow script delays the calls after it.

When changes apply

  • Both settings apply to calls that end after the change, within a minute or two. No restart is needed.
  • Existing call records are not changed. If you map a column to a new variable, its old values remain under the new meaning.
  • The log records when a script changes no rows or an unexpected number of rows. Check it after changing the script.
