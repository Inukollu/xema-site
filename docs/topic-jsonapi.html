jsonapi

A Json Api XApp calls a web service while the caller waits, reads values from the JSON response, and stores them in call variables. The call then continues from where it came in.

Request

  • HTTP verb and URL define the request.
  • Headers is a JSON object of key-value pairs, for example authorization and content type.
  • Body is sent as JSON with verbs that accept a body.

Call values

Names in braces are replaced before the request is sent, in the URL, headers and body. {CLI} and {ANI} are the caller's number. Any other name is a variable set earlier in the call. For example: https://crm.example.com/customer?phone={CLI}&ref={ACCOUNT_NO}

Response

Each of the five rows sets one variable: its name and a JSON query that selects its value in the response, such as $.customer.name or $.orders[0].status. Variable 1 is always enabled; enable the others as needed.

Behaviour

  • The response must be a JSON object.
  • If the service returns an error, fails or times out, the variables are empty. Always add a route for that case.
  • The caller waits while the request runs, so use a service that responds quickly.
  • The request is sent after a short delay, so that variables set just before are available.
  • The name cannot be changed later; flows refer to this XApp by name.

Commands

  • xema jsonapi add
  • xema jsonapi fields
  • xema jsonapi remove
  • xema jsonapi set
  • xema jsonapi show
  • xema jsonapis
