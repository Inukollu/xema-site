Topics

What each thing in Xema is and how it behaves: the same pages the console's help panels, xema help <topic> and man xema-<topic> show.

  • agent: Agents are the people who take and place calls.
  • agentflow: Agent actions are buttons the agent can use during a call from a queue, to transfer the caller to a phone or
  • agentphone: The transfer action is a button the agent can use during a call from a queue to transfer the caller to another
  • aiagent: An AI Conversation Agent greets the caller and holds an open conversation, using its tools to answer
  • aiinput: An AI Input Agent plays the announcement, listens to the caller and sets the output variables.
  • aiprovider: An AI provider is an AI service used by the AI agent XApps: the vendor, the endpoint, the model and the
  • ani: A phone number pool is a range of numbers, from its first to its last.
  • audio: An audio is a recording played to callers: a prompt, a menu, a thank-you message or a promotion.
  • backup: A backup is a copy of the database, taken on the server that has the database role.
  • binding: A network binding sets what one of a server's addresses is used for.
  • break: Breaks are what agents can select when they step away, such as lunch, training or a meeting.
  • busyhours: The busy hour is the hour of the day with the most traffic.
  • callcounter: The call counter XApp counts how often a number has called.
  • callerflow: A caller action is a key a caller can press while waiting in a queue.
  • cdr: Xema writes a call detail record for every call.
  • cluster-settings: Settings control how a cluster behaves.
  • cluster: A cluster is a group of servers at one location that work as one contact center.
  • cors: A cluster lets pages from other sites call it only when it names those sites.
  • crm: A CRM link is a URL that opens the caller's record in your CRM when a call from a queue is offered to an agent,
  • customapp: A Custom App XApp sends the call to a custom dial plan written for this cluster outside Xema Manager.
  • dashboard: The dashboard is a read-only overview of the platform's current activity.
  • dataset: A dataset is a list of numbers for dialers to call.
  • dialer: A dialer places outbound calls automatically.
  • dialout: A Dial Out XApp sends the call out over a trunk and connects the caller to whoever answers.
  • dns: DNS settings decide how a server resolves names to addresses.
  • flags: Flags switch optional features of a cluster on or off: the panels Agent UI offers, and whether an agent must
  • flow: A flow is a call flow: a named set of blocks, each a group of steps, that decides what happens to a call.
  • forecast: The forecast estimates the calls each queue will receive in every 15-minute interval.
  • hosts: The hosts are the names and addresses a cluster's services answer at.
  • jsonapi: A Json Api XApp calls a web service while the caller waits, reads values from the JSON response, and stores
  • language: A language is one that calls can be handled in.
  • loglevel: A log level sets how much a Xema service writes to its log.
  • logs: Each service on a Xema server writes its own log.
  • lookup: A Dataset Lookup XApp looks up a number in a dataset and copies values from the matching row into variables.
  • missed-call: A missed call is a call that arrived on a trunk for a number the trunk does not route: the number has no DNI
  • music: Hold music is played to callers waiting in a queue.
  • network-configuration: The network configuration is the set of files that will be written to the server, one per managed interface.
  • network-device: Network devices are the other devices the server can see on the network attached to an interface, such as
  • network-interface: A network interface is a server's connection to a network.
  • network-realm: A SIP realm isolates one carrier's connection from everything else on the server.
  • network-routing: A route tells the server where to send traffic for a particular network.
  • network-vlan: A VLAN carries several separate networks over one physical cable.
  • number: A number is a dialled number that arrives on a trunk, and the XApp it is routed to.
  • phone: A phone is a SIP extension: the number a phone device registers with and the line an agent takes calls on.
  • phonegroup: A phone group holds phones that share the same settings.
  • process-dashboard: Every process you look after, in one place.
  • process-overview: One process at a glance: who works in it, the queues and dialers it uses, and the datasets it dials.
  • process: A process is a line of business: its agents, teams, queues, dialers and datasets, with owners who manage
  • queue: A queue holds callers until an agent with the required skills is available.
  • report: Reports are what users run in Data Portal.
  • role: A role is a set of permissions that can be assigned to users.
  • schedule: A schedule held the hours in which the dialers on it could dial.
  • server: The server settings are the operating system's settings for a server: its name, its time and its SSH access.
  • service: Services are the systemd units on a server: Xema's own services and the infrastructure they depend on.
  • shell: The shell is a terminal on a server of the cluster, equivalent to an ssh session.
  • sip-logger: SIP Logger captures SIP signalling arriving at a server.
  • sip-session: A SIP session is the full list of SIP messages for one call, in order.
  • skill: A skill marks what an agent can handle, such as a language, a product line or a type of request.
  • standard-report: Standard reports are provided with Xema and their content cannot be changed.
  • team: A team groups agents who work together.
  • trunk: A trunk is the SIP connection between Xema and a carrier.
  • webhook: A webhook is a request Xema sends to another system's URL.
  • xapp: XApps are the applications a call can be sent to.
